# 关务AEO认证稽核系统 · 项目总结

> 基于海关总署令第282号（2026年4月施行）及南京海关AEO认证标准检查表
> 项目状态：✅ 完成（单页应用原型 + 本地服务器部署）

---

## 一、项目背景

### 业务目标

搭建一套企业内部使用的 **AEO（Authorized Economic Operator）合规管理系统**，满足三大核心需求：

1. **展示海关标准给各部门** — 30条认证标准 → 9部门映射 → 证据三件套
2. **分发任务到各部门** — 创建→执行→上传证据→审核→归档的全流程
3. **演示给海关看** — 一键切换海关演示模式，只读展示所有合规证据

### 政策依据

| 文件 | 说明 |
|------|------|
| 海关总署令第282号 | 《信用管理办法》，2026年4月1日施行 |
| 海关总署公告2026年第34号 | 《海关高级认证企业标准》 |
| 海关总署公告2026年第35号 | 高级认证企业简易复核程序 |
| **南京海关检查表** | 南京海关AEO进出口收发货人高级认证标准检查表（25项） |

## 七、数据模型

### localStorage（9个键）

| 键(aeo_前缀) | 存储内容 |
|:-------------|---------|
| `aeo_tasks` | 任务列表 (TSK-2026-XXXX格式) |
| `aeo_assessmentResults` | 自评答案存档 |
| `aeo_assessmentAnswers` | 当前自评状态 |

| `aeo_lastAssessmentDate` | 最近日期 |
| `aeo_auditLogs` | 审计日志 |
| `aeo_notifications` | 通知列表 |
| `aeo_currentUser` | 当前用户 {role, name} |
| `aeo_financeData` | 财务指标 |

### IndexedDB

- 数据库名: `AEOFileStore`
- Object Store: `files`（autoIncrement）
- 索引: category、name
- 分类: document（制度文件）、training（培训资料）
- 单文件限制: 制度≤50MB、培训≤200MB

## 八、安全措施

| 措施 | 说明 |
|:----|------|
| **XSS防护** | `createTextNode()` 而非 innerHTML + `escapeHtml()` 工具函数 |
| **Basic Auth** | 部署层密码保护，未认证返回401 |
| **角色UI控制** | 海关查看者隐藏编辑/新建按钮 |
| **目录穿越防护** | 服务器校验路径是否在ROOT内 |
| **文件类型限制** | accept属性 + 大小限制 |
| **删除确认** | 所有删除/重置操作二次confirm |

## 十、当前限制与改进方向

### 架构层面

| 问题 | 建议方案 |
|:----|---------|
| **纯前端无后端** | 数据在浏览器本地，换设备/清缓存即丢 → Node.js + SQLite |
| **无真实用户认证** | 下拉选择角色，无密码验证 → OAuth2/LDAP |
| **单机协作不能** | 多人同时操作覆盖数据 → WebSocket实时同步/REST API |
| **无数据备份** | 浏览器升级误清全丢 → 自动云备份 |

### 功能层面

| 缺失功能 | 优先级 |
|---------|:------:|
| 供应商真API对接（信用中国） | P1 |
| 日历/Gantt视图完善 | P1 |
| 消息推送（不在线收不到） | P2 |
| 评分权重可配置 | P2 |
| 版本管理（标准更新追溯） | P2 |

### 代码层面

| 问题 | 影响 |
|:----|:----|
| **1830行单文件** | 任何修改都要动整个文件 |
| **无类型检查** | 纯JS，运行时才暴露错误 |
| **无单元测试** | 评分算法/状态机无自动化测试 |
| **无CI/CD** | 每次修改手动部署 |
