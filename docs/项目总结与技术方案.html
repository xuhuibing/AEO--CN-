一 项目概述

1.1 项目背景

AEO（Authorized Economic Operator，经认证的经营者）是海关对企业信用状况和守法水平的认证制度。通过AEO高级认证的企业可享受通关便利化、降低查验率等优惠措施。

本系统旨在帮助企业全面管理AEO认证全过程，从标准学习、合规自评、整改跟踪到证据归档，实现AEO认证工作的数字化和流程化管理。

1.2 系统定位

  • 面向对象：关务人员、部门AEO对接人、内审员、企业高管、海关查看者
  • 核心目标：帮助企业高效通过AEO高级认证/认证企业的标准审核
  • 部署方式：本地私有化部署，单机运行

1.3 技术栈

层级技术选型说明
后端Node.js HTTP模块无框架，纯http.createServer
数据库SQLite (better-sqlite3)嵌入式数据库，无需独立服务

综合驾驶舱，展示系统关键指标和快速入口。

3.5 合规自评 (Assessment)

  • 按维度分组的问卷（每种标准类型独立问卷）
  • 三级选项：已达标 / 部分达标 / 未达标
  • 即时分数计算和进度条
  • 历史评估记录查看
  • 评估结果导出（合并报告）

3.6 认证自查 (Self Check)

  • 按标准维度的自查清单
  • 填写实际情况与达标证据
  • 状态标记：未开始 / 进行中 / 已完成

3.7 标准宣贯 (Standards Training)

  • 各维度的部门培训情况
  • 宣贯记录（时间、参与人、内容概要）

3.8 供应商信用 (Supplier)

  • 供应商名录管理（CRUD）
  • 海关信用查询记录
  • 信用状态跟踪（良好/异常/失信）

3.9 财务指标 (Finance)

  • 多年度财务数据录入
  • 关键指标：审计报告意见、资产负债率、现金比率、流动比率、净利润、营业利润率、毛利率
  • 自动判断达标状态

3.10 任务管理 (Tasks)

  • 任务CRUD（与认证标准关联）
  • 状态流转：待下发 → 执行中 → 审核中 → 已完成 → 已关闭
  • 看板视图 / 列表视图切换
  • 日历时间线 + 批量下发 + 过滤器

3.11 内部审计 (Audit)

  • 审计计划管理
  • 审计发现与整改跟踪
  • 审计报告归档

3.12 制度文件 (Documents)

  • 制度文件分类管理
  • 文件上传（逐文件/多文件）
  • 按类别/年份/模块筛选 + 在线预览和下载

3.13 培训中心 (Training)

  • 培训记录管理
  • 培训计划制定、参训人员管理

3.14 年度归档 (Annual Archive)

  • 年度档案材料整理
  • 按维度归档证据材料

3.15 海关演示 (Demo)

  • 面向海关的演示模式
  • 证据材料时间线展示

3.16 用户管理 (User Management)

  • 用户CRUD（关务经理权限）
  • 角色权限编辑、密码修改/重置
  • 用户激活/停用、在线会话列表

3.17 审批中心 (Approvals)

  • 数据变更审批流程
  • 审批列表（待处理/已通过/已驳回）
  • 审批操作（通过/驳回 + 审批意见）
  • 变更前后对比显示

3.18 整改跟踪 (Rectification) ⭐ 核心模块

完整的问题跟踪与验收流程。

状态流转： 发起人创建 → 待处理(open) → 处理中(in_progress) → 待验收(pending_accept) → 已闭环(closed)
  • 新建整改表单：发起部门、发起人、日期、问题描述、严重程度
  • 跟进部门、责任人、截止日期
  • 验收部门（双部门：关务部 □ 审计部门 □）
  • 审批操作：提交验收 / 退回 / 关闭
  • 确认人、确认时间自动记录
  • 超期整改变色预警

3.19 系统设置 (System Settings)

  • 系统参数配置
  • 数据库备份（手动触发 + 自动保留30份）
  • 数据完整性检查 + 审计日志查看
  • 数据导入/导出

十一 项目关键设计决策

纯原生实现

选择Node.js原生HTTP模块 + 原生JS字符串拼接渲染：

  • 零框架依赖，部署简单（仅需Node.js）
  • 适合企业内网环境，无需编译工具链
  • 单文件可维护，减少学习成本
  • 适合海关内网/专网部署场景

SQLite 数据库

选择SQLite而非MySQL/PostgreSQL：

  • 零运维，无需独立数据库服务
  • 自动备份，30份滚动保留
  • WAL模式提升并发性能
  • 兼容旧JSON存储模式（通过data_versions表）

权限模型

采用RBAC（基于角色的访问控制）：

  • 5种预定义角色覆盖全部使用场景
  • 细粒度权限控制（permission级别的检查）
  • Basic Auth兼容旧系统集成

认证标准数据存储

标准数据直接在 standards-data.js 中编码为JavaScript数据结构：

  • 避免复杂的数据库查询
  • 支持两套标准（advanced/certified）
  • 支持子分类结构（subcategories）
  • flattenStandardsData() 向后兼容

待优化方向

  1. 标准完成证据：为每个标准项绑定具体证据文件，支持证据上传和管理
  2. 提醒与通知：任务截止提醒、整改超期预警、审批通知推送
  3. 评分模型：更精细的评分算法，支持海关评分加权
  4. 多年度对比：历年评估得分趋势
  5. 报告导出：完整的AEO认证申请报告一键导出（PDF/Word）
  6. 移动端适配：更好的手机浏览器体验
  7. 飞书集成深化：审批流程在飞书内完成
  8. 多语言支持：英文版界面（适用外资企业）
  9. LDAP集成：对接企业AD/LDAP统一认证
