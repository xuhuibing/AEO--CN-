# 关务AEO认证稽核系统 · 实施计划

> 基于海关总署令第282号及配套标准  
> 目标：完善可在企业落地的AEO合规管理系统  
> 参考草稿：https://xuhuibing.github.io/CN-AEO/

---

## 一、现状评估

### 现有草稿完成度

| 模块 | 完成度 | 现状说明 |
|------|:------:|---------|
| 系统首页 (Dashboard) | ✅ 70% | 评分UI框架完整，数据为静态占位（显示"--"），未接入真实计算 |

| 供应商信用 (Supplier) | ⚠️ 50% | 查询框+外部链接+示例结果展示，**无真实API对接** |

### 核心缺口

```
用户需求             草稿现状
────────────────────────────────────────────────
① 展示海关标准给各部门 → 有标准但无部门映射
② 分发任务到各部门    → 任务管理几乎为空
③ 演示给海关看        → 没有演示模式
```

#### c) 证据三件套

- 📄 **制度文件**（有没有制定制度）

- ✅ **审批留痕**（有没有审核确认）

海关现在要求"制度+执行+审批"三者缺一不可。

## 六、技术方案

### 技术栈

| 项目 | 选择 |
|------|------|
| 前端框架 | 纯HTML+Tailwind CSS+原生JS（延续草稿风格） |
| 图表 | Chart.js（已有） |
| 图标 | Font Awesome 6（已有） |
| 数据存储 | localStorage（浏览器本地）→ 后续可对接后端API |
| 部署方式 | GitHub Pages / 企业内网静态服务器 |

### 数据存储策略

**第一阶段（当前）**：所有数据使用JavaScript对象 + localStorage
- standardsData：标准条目库
- tasks：任务列表
- evidence：证据记录
- assessmentResults：自评结果

**第二阶段（后续）**：对接后端API
- RESTful API 替代 localStorage
- 数据库持久化（MySQL/PostgreSQL）
- 用户权限管理（RBAC）
