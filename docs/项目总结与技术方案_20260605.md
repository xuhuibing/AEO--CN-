## 一、项目概述

### 1.1 项目背景

AEO（Authorized Economic Operator，经认证的经营者）是海关对企业信用状况和守法水平的认证制度。通过AEO高级认证的企业可享受通关便利化、降低查验率等优惠措施。

本系统旨在帮助企业全面管理AEO认证全过程，从标准学习、合规自评、整改跟踪到证据归档，实现AEO认证工作的数字化和流程化管理。

### 1.2 系统定位

- 面向对象：关务人员、部门AEO对接人、内审员、企业高管、海关查看者
- 核心目标：帮助企业高效通过AEO高级认证/认证企业的标准审核
- 部署方式：本地私有化部署，单机运行

### 1.3 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 后端 | Node.js + HTTP内置模块 | 无框架，纯http.createServer |
| 数据库 | SQLite (better-sqlite3) | 嵌入式数据库，无需独立服务 |
| 前端 | 原生JS + Tailwind CSS | 纯字符串拼接渲染，无前端框架 |
| 认证 | bcryptjs + uuid | 密码加密 + Session Token |
| 图标 | Font Awesome 6免费版 | 图标库 |
| 图表 | Chart.js (CDN) | 仪表盘图表 |

## 三、核心功能模块

### 3.1 系统首页 (Dashboard)

综合驾驶舱，展示系统的关键指标和快速入口。

**功能要点：**
- 总体得分仪表盘（得分环 + 评分说明弹窗）
- 统计卡片：认证标准、合规自评、任务完成率、整改超期数
- 动态进度条：各维度完成情况
- 快速入口：完善企业信息、维护供应商名录、录入财务指标、开始标准自查
- 新手引导弹窗（首次使用）

**数据来源：** 各模块汇总统计（标准完成度、自评分数、任务状态、整改超期等）

### 3.2 企业介绍 (Enterprise)

**功能要点：**
- 公司基本信息管理（名称、统一社会信用代码、海关编码、注册日期等）
- 进出口数据编辑（年度进出口额、单量、商品类别等）
- 公司介绍设置弹窗

**内置核心法规：**

### 3.4 认证标准 (Standards) ⭐ 核心模块

AEO认证标准的知识库，以维度+子分类+标准项三层结构展示。

**两种标准类型：**
| 类型 | 维度数 | 标准项 | 适用 |
|------|-------|-------|------|
| 高级认证企业标准 | 7维度 | 74项 | 申请AEO高级认证 |
| 认证企业标准 | 6维度 | 62项 | 申请AEO一般认证 |

**7大维度：**
| 维度 | 颜色 | 子分类 | 说明 |
|------|------|-------|------|
| 内部控制 | blue | 海关业务培训、组织机构和岗位职责、单证保管、进出口业务操作 | 核心管理规范 |
| 财务状况 | emerald | 审计报告、偿债能力、盈利能力、破产风险 | 财务健康度 |
| 守法规范 | amber | 注册信息、守法合规、进出口业务规范、外部信用 | 合规记录 |
| 贸易安全 | red | 场所/进入/人员/商业伙伴/货物/集装箱/运输工具/危机/培训 | 供应链安全 |
| 信息系统与安全 | cyan | 信息系统建设、信息安全 | IT管理 |
| 内部审计与改进 | pink | 内部审计、改进机制 | 内审与持续改进 |
| 附加标准 | violet | 加分项 | 高级认证额外加分 |

**展示方式：**
- 维度统计卡片（可点击展开/收起对应维度）
- 搜索栏实时过滤
- 桌面端：TOC目录侧边栏 + 内容区手风琴
- 移动端：水平滚动标签导航
- 切换视图：按维度查看 / 按部门查看

**标准项卡片内容：**
- 标准编号 + 名称 + 官方编号
- 标准要求（常驻显示）
- 负责部门 + 支持部门 + 执行频率
- 检查文件要求、询问内容、实地查看要求、随机抽查要求
- 样本资料、检查要点
- 证据要求说明
- 证据完成状态（制度/记录/审批三色标记）

### 3.5 合规自评 (Assessment)

基于标准的自我评估问卷模块。

**功能要点：**
- 按维度分组的问卷（每种标准类型独立问卷）
- 三级选项：已达标 / 部分达标 / 未达标
- 即时分数计算和进度条
- 历史评估记录查看
- 评估结果导出（合并报告）

**评分机制：**
- 每个维度的得分百分比独立计算
- 总体得分 = 所有维度得分的加权平均
- 自动判断达标状态（得分 ≥ 80% 为达标）

### 3.6 认证自查 (Self Check)

**功能要点：**
- 按认证标准维度展开的自查清单
- 填写实际情况与达标证据
- 状态标记：未开始 / 进行中 / 已完成
- 自查进度跟踪

### 3.7 标准宣贯 (Standards Training)

**功能要点：**
- 各维度标准的部门培训情况
- 宣贯记录（时间、参与人、内容概要）
- 培训完成度

### 3.8 供应商信用 (Supplier)

**功能要点：**
- 供应商名录管理（CRUD）

### 3.9 财务指标 (Finance)

### 3.18 整改跟踪 (Rectification) ⭐ 核心模块

完整的整改问题跟踪与验收流程。

**问题状态流转：**
```
发起人创建 → 待处理(open)
                 ↓ 负责人开始处理
               处理中(in_progress)
                 ↓ 标记待验收
               待验收(pending_accept)  ← 关务部 + 审计部门验收
                 ↓ 两部门均确认
               已闭环(closed)
```

**功能要点：**
- 新建整改表单：发起部门、发起人、日期、问题描述、严重程度
- 跟进部门、责任人、截止日期
- 验收部门（双部门：关务部 □ 审计部门 □）
- 审批操作：提交验收 / 退回 / 关闭
- 确认人、确认时间自动记录
- 超期整改变色预警
- 状态统计卡片

### 3.19 系统设置 (System Settings)

**功能要点：**
- 系统参数配置
- 数据库备份（手动触发 + 自动保留30份）
- 数据完整性检查

## 四、后端 API 设计

服务器基于Node.js原生`http.createServer`，支持完整的RESTful API。默认端口：`3080`。

### 4.1 认证与鉴权

**三种认证方式：**
| 方式 | 头格式 | 适用场景 |
|------|-------|---------|
| Basic Auth | `Authorization: Basic base64(user:pass)` | 向后兼容、API客户端 |
| Bearer Token | `Authorization: Bearer <session_token>` | Web前端会话 |
| API Key | `X-API-Key: <key>` | 第三方系统集成 |

**默认登录凭证：** `admin / admin123`（首次启动自动创建）

## 十一、项目关键设计决策

### 11.1 纯原生实现

选择Node.js原生HTTP模块 + 原生JS字符串拼接渲染，原因：
- 零框架依赖，部署简单（仅需Node.js）
- 适合企业内网环境，无需编译工具链
- 单文件可维护，减少学习成本
- 适合海关内网/专网部署场景

### 10.2 SQLite 数据库

选择SQLite而非MySQL/PostgreSQL：
- 零运维，无需独立数据库服务
- 自动备份，30份滚动保留
- WAL模式提升并发性能
- 兼容旧JSON存储模式（通过data_versions表）

### 10.3 权限模型

采用RBAC（基于角色的访问控制）：
- 5种预定义角色覆盖全部使用场景
- 细粒度权限控制（permission级别的检查）
- Basic Auth兼容旧系统集成

### 10.4 认证标准数据存储

标准数据直接在 `standards-data.js` 中编码为JavaScript数据结构：
- 避免复杂的数据库查询
- 支持两套标准（advanced/certified）
- 支持子分类结构（subcategories）
- flattenStandardsData() 向后兼容
