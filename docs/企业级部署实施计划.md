### 3.2 数据库设计（SQLite）

**users 表**：
```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT UNIQUE NOT NULL,       -- 登录账号
  password_hash TEXT NOT NULL,         -- bcrypt 哈希
  display_name TEXT NOT NULL,          -- 显示名称
  role TEXT NOT NULL,                  -- role: customs_manager / dept_contact / auditor / executive / customs_viewer
  department TEXT,                     -- 所属部门
  email TEXT,                          -- 联系方式
  is_active INTEGER DEFAULT 1,        -- 启用/禁用
  created_at TEXT DEFAULT (datetime('now')),
  last_login TEXT
);
```

**tasks 表**：
```sql
CREATE TABLE tasks (
  id TEXT PRIMARY KEY,                 -- TSK-2026-XXXX
  name TEXT NOT NULL,
  standard_id TEXT,                    -- 关联 IC-01, TS-01 等
  department TEXT NOT NULL,            -- 执行部门
  owner TEXT NOT NULL,                 -- 负责人
  due TEXT NOT NULL,                   -- 截止日期 YYYY-MM-DD
  status TEXT NOT NULL,                -- 待下发/执行中/审核中/已完成/已关闭
  requirement TEXT,                    -- 工作要求
  attachment_requirement TEXT,         -- 附件要求
  priority INTEGER DEFAULT 1,         -- 优先级
  created_by TEXT,                     -- 创建人
  created_at TEXT,
  updated_at TEXT
);
```

**task_evidence 表**（任务执行证据，新增）：
```sql
CREATE TABLE task_evidence (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id TEXT NOT NULL REFERENCES tasks(id),
  file_name TEXT NOT NULL,
  file_path TEXT NOT NULL,
  file_size INTEGER,
  description TEXT,
  uploaded_by TEXT,
  uploaded_at TEXT DEFAULT (datetime('now'))
);
```

**standard_documents 表**（标准-文件关联，新增）：
```sql
CREATE TABLE standard_documents (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  standard_id TEXT NOT NULL,           -- IC-01 等
  evidence_type TEXT NOT NULL,         -- policy / record / approval / other
  file_name TEXT NOT NULL,
  file_path TEXT NOT NULL,
  description TEXT,
  uploaded_by TEXT,
  uploaded_at TEXT DEFAULT (datetime('now'))
);
```

其他表类似迁移（assessment、audit_log、notifications、company_info、finance_data）。

### 3.3 认证流程

```
浏览器 → POST /api/auth/login → { username, password }
  ↓
服务端校验 → bcrypt.compare(password, hash)
  ↓
成功 → 签发 JWT Token（含 userId, role, department, name）
  ↓
返回 → { token, user: { name, role, department } }
  ↓
前端存储 Token → 每次 API 请求带 Authorization: Bearer <token>
```

- Token 有效期：24 小时
- 支持刷新：`POST /api/auth/refresh`
- 服务端 JWT 中间件校验所有 /api/* 请求（除 /api/auth/* 外）

### 3.4 数据迁移方案

从现有的 localStorage / JSON 文件迁移到 SQLite：

```javascript
// migrations/migrate.js
// 1. 从 data/*.json 读取所有现有数据
// 2. 创建对应用户（默认 admin/admin123）
// 3. INSERT INTO 各表
// 4. 生成迁移报告
```

## 四、阶段2：文件存储服务端化 + 证据关联

### 目标
- IndexedDB 文件改为服务端上传
- 25条认证标准挂载证据文件

### 4.1 文件上传 API

```javascript
POST /api/files/upload?type=document|training|evidence
Content-Type: multipart/form-data
Authorization: Bearer <token>

→ 200 { fileId, fileName, filePath, fileSize }
```

- 文件存储到 `uploads/{type}/{yyyy-mm}/{uuid}.{ext}`
- 限制：单文件 50MB（制度）/ 200MB（培训）
- 允许类型：pdf, doc, docx, xlsx, jpg, png, zip

### 4.2 标准关联文件

```javascript
POST /api/standards/:id/documents
Body: { fileId, evidenceType: 'policy'|'record'|'approval' }

GET /api/standards/:id/documents
→ 按 evidenceType 分组的文件列表
```

### 4.3 任务证据上传

```javascript
POST /api/tasks/:id/evidence
Body: { fileId, description }

GET /api/tasks/:id/evidence
→ 文件列表（含缩略图）
```

## 七、阶段5：部署 + 运维

### 7.1 生产部署方案

```bash
# 1. 服务器要求
Node.js >= 18.x
SQLite >= 3.x 或 MySQL >= 8.x
Nginx >= 1.24
系统: Ubuntu 22.04 / CentOS 7+

# 2. Nginx 配置
server {
    listen 443 ssl;
    server_name aeo.yourcompany.com;

    # SSL 证书
    ssl_certificate /etc/nginx/ssl/aeo.crt;
    ssl_certificate_key /etc/nginx/ssl/aeo.key;

    # API 转发
    location /api/ {
        proxy_pass http://127.0.0.1:3080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 文件下载
    location /uploads/ {
        alias /opt/aeo-system/uploads/;
    }

    # 前端静态文件
    location / {
        root /opt/aeo-system/src;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}
```

### 7.2 systemd 服务

```ini
# /etc/systemd/system/aeo.service
```

### 7.3 运维脚本

```bash

DATE=$(date +%Y%m%d)
# 备份数据库
cp /opt/aeo-system/data/database.sqlite /opt/aeo-system/backups/db_$DATE.sqlite
```

## 九、风险和注意事项

### 技术风险

| 风险 | 概率 | 影响 | 应对 |
|:----|:---:|:----|:----|
| SQLite 并发写入冲突 | 中 | 高 | 用 WAL 模式 + 重试机制，或上 MySQL |
| 数据迁移丢失 | 低 | 高 | 迁移前完整备份，分批验证 |
| 旧版浏览器兼容 | 低 | 中 | 支持 Chrome/Firefox/Edge 最新两版 |
| 大文件上传超时 | 中 | 低 | 分片上传、进度条、超时重试 |

### 建议的技术选型

- **数据库**：中小团队（<50人同时使用）选 SQLite 够用，轻量免维护；规模更大选 MySQL
- **Node.js**：保持纯 JS 无编译步骤，方便运维快速定位
- **前端**：继续原生 JS（不加 React/Vue），避免增加构建步骤和依赖复杂度

### 关于"模块化"的说明

当前 1970 行单文件、63 个函数全部在全局作用域，建议阶段1拆分时：

1. 每个 JS 模块用 IIFE + 命名空间模式（不加 webpack/rollup）
2. 全局变量保留在 `window.AEO = {}` 命名空间下
3. 避免闭包陷阱，保持可维护性

```javascript
// src/js/tasks.js
(function() {
  'use strict';
  const M = window.AEO = window.AEO || {};

  M.renderTaskTable = function() { ... };
  M.createTask = function() { ... };
  // ...
})();
```
