## 1. 项目背景

### 1.1 业务需求

基于海关总署令第282号（2026年4月1日施行）及配套公告第34号/第35号，构建一套企业内部使用的 **AEO（Authorized Economic Operator）合规管理系统**，满足以下三大目标：

1. **展示海关标准给各部门** — 30条认证标准 + 9部门映射 + 证据三件套
2. **分发任务到各部门** — 任务创建 → 执行 → 上传证据 → 审核 → 归档
3. **演示给海关看** — 一键切换海关演示模式，只读展示所有合规证据

### 1.2 参考依据

| 文件 | 说明 |
|------|------|
| 海关总署令第282号 | 《中华人民共和国海关注册登记和备案企业信用管理办法》 |
| 海关总署公告2026年第34号 | 《海关高级认证企业标准》《海关认证企业标准》 |
| 海关总署公告2026年第35号 | 高级认证企业简易复核程序 |

## 4. 技术栈

| 项目 | 选择 | 版本 |
|------|------|:----:|
| **前端框架** | 纯 HTML + Tailwind CSS + 原生 JS | Tailwind CDN |
| **图表库** | Chart.js | CDN |
| **图标库** | Font Awesome 6 | CDN (free) |
| **数据存储** | `localStorage`（结构化数据）+ `IndexedDB`（文件） | 浏览器内置 |
| **文件存储** | IndexedDB Object Store (`AEOFileStore`) | 异步读写 |
| **认证方式** | 前端角色选择（演示环境） | localStorage 持久化 |
| **部署方式** | 静态页面（GitHub Pages / 企业内网） | 单文件 HTML |

### 4.1 外部依赖（CDN）

```html
<!-- 样式 -->
<script src="https://cdn.tailwindcss.com"></script>
<!-- 图表 -->
<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
<!-- 图标 -->
<link href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css" rel="stylesheet">
```

### 4.2 核心技术选型理由

- **纯静态单页**：无需服务器，开箱即用，适合企业内网部署
- **localStorage**：简单可靠，适合小规模结构化数据（任务、自评、日志）
- **IndexedDB**：浏览器原生支持大文件存储（单文件上限可配置），适合证据文件管理
- **Tailwind CDN**：零构建步骤，快速迭代原型

## 5. 数据模型

### 5.1 localStorage 命名空间

所有键以 `aeo_` 为前缀，避免污染：

| 键 | 存储内容 | 数据结构 |
|:---|---------|---------|
| `aeo_tasks` | 任务列表 | `Task[]` |
| `aeo_assessmentResults` | 自评答案 | `{key: value}` |
| `aeo_assessmentAnswers` | 当前答案状态 | `{key: value}` |
| `aeo_lastAssessmentScore` | 最近自评得分 | `number` |
| `aeo_lastAssessmentDate` | 最近自评日期 | `string (ISO)` |
| `aeo_auditLogs` | 审计日志 | `LogEntry[]` |
| `aeo_notifications` | 通知列表 | `Notification[]` |
| `aeo_currentUser` | 当前登录用户 | `{role, name}` |
| `aeo_financeData` | 财务指标数据 | `{[label]: value}` |

### 5.2 Token 数据结构

```typescript
interface Task {
  id: string;              // TSK-2026-XXXX
  name: string;            // 任务名称
  standard: string;        // 关联标准ID (如 IC-03)
  dept: string;            // 执行部门
  owner: string;           // 负责人
  due: string;             // 截止日期 (YYYY-MM-DD)
  req: string;             // 执行要求
  attachReq: string;       // 附件要求
  status: TaskStatus;      // 待下发 | 执行中 | 审核中 | 已完成 | 已关闭
  evidence: string[];      // 证据文件ID列表
  createdAt: string;       // 创建时间 (ISO)
}

interface StandardItem {
  id: string;              // IC-01, TS-S01, ...
  name: string;            // 标准名称
  desc: string;            // 标准描述
  dept: string;            // 主责部门
  supportDept: string;     // 配合部门
  frequency: string;       // 执行频次
  evidence: {
    policy: boolean;       // 制度文件
    record: boolean;       // 执行记录
    approval: boolean;     // 审批留痕
  };
  evidenceDesc: string;    // 证据要求描述
}

interface LogEntry {
  ts: string;              // 时间戳 (ISO)
  user: string;            // 用户名
  role: string;            // 角色
  action: string;          // 操作描述
  type: string;            // task | standards | assessment | auth | data | general
  detail: string;          // 详细说明
}
```

### 5.3 IndexedDB 数据模型

**数据库名**: `AEOFileStore`

**Object Store**: `files`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `number` (autoIncrement) | 文件ID |
| `name` | `string` | 文件名 |
| `size` | `number` | 文件大小(bytes) |
| `type` | `string` | MIME类型 |
| `category` | `string` | 分类 (`document` / `training`) |
| `data` | `string` (DataURL) | 文件内容(base64) |
| `uploadedAt` | `string` (ISO) | 上传时间 |

**索引**:
- `category` — 按分类查询
- `name` — 按名称查询

## 6. 模块详解

### 6.1 认证标准模块（核心）

**标准数量**：

| 维度 | 高级认证 | 认证企业 | 涉及部门 |
|:----|:--------:|:--------:|:--------|
| 内部控制 (IC) | 7条 | 2条 | 关务部、IT部、内审部 |
| 财务状况 (FI) | 3条 | 1条 | 财务部 |
| 守法规范 (LC) | 4条 | 1条 | 关务部、法务部、HR |
| 贸易安全 (TS) | 16条 | 2条 | 行政部、物流/仓储、HR、采购部、IT部 |
| **合计** | **30条** | **6条** | **9部门** |

**证据三件套**：每条标准追踪三种证据的完成状态：
- 📄 **制度文件**（有没有制定制度）
- 📋 **执行记录**（有没有按制度执行）
- ✅ **审批留痕**（有没有审核确认）

**双视图切换**：
- **按维度查看** — 4大维度卡片，展示各维度证据完成率
- **按部门查看** — 9部门分组，展示各部门证据完成状态

### 6.2 任务管理模块（核心）

**状态流转**：
```
待下发 → 执行中 → 审核中 → 已完成 → 已关闭
                     ↑        ↓
                  退回重做  通过
```

**数据统计**：
- 5个统计卡片（待下发/执行中/审核中/已超期/已完成）
- 9部门看板（各部门待办+进度条）
- 全部任务列表（筛选+排序+checkbox）

**功能**：
- 创建任务（名称、关联标准、部门、负责人、截止日期、要求）
- 状态变更（下发/提交/通过/退回 — 均需二次确认）
- 批量操作（全选、批量下发、批量完成）
- 日历时间线视图

### 6.3 海关演示模块

**触发方式**：页面右上角「全屏演示模式」按钮

**进入后变化**：
- 侧边栏隐藏
- 页面底部显示水印"演示模式 · 非生产环境 · 数据仅供展示"
- 主内容区切换为演示专用布局

**演示内容**：
- 4维度标签切换（内部控制/财务状况/守法规范/贸易安全）
- 每条标准展开查看证据详情（制度+记录+审批）
- 证据连续性时间线（近6个月月度覆盖图）
- 综合合规度分数展示
- 导出演示报告（window.print）

## 7. 安全措施

| 措施 | 说明 |
|------|------|
| **XSS防护** | `editEnterprise()` 使用 `createTextNode()` 而非 `innerHTML` |
| **HTML转义** | `escapeHtml()` 工具函数用于所有用户输入展示 |
| **角色UI控制** | 海关查看者隐藏"新建任务"、"编辑企业信息"等按钮 |
| **数据隔离** | 仅前端控制，无后端鉴权（演示环境限制） |
| **文件类型限制** | 上传accept属性限制可选文件类型 |
| **文件大小限制** | 制度文件≤50MB，培训资料≤200MB |
| **删除确认** | 所有删除/重置操作需要二次confirm确认 |

## 9. 遗留不足与改进方向

### 9.1 架构层面

| 问题 | 影响 | 建议方案 |
|------|------|---------|
| **纯前端无后端** | 数据在浏览器本地，清缓存全丢，换设备不可用 | Node.js + SQLite / 低代码平台 |
| **无真实用户认证** | 下拉选择角色，无密码验证 | OAuth2 / LDAP / 钉钉扫码 |
| **单机协作不能** | 多人同时操作覆盖数据 | WebSocket 实时同步 / REST API |
| **数据无备份** | 浏览器升级/误清全丢 | 自动云备份 / 定期导出提醒 |

### 9.2 安全与合规

| 问题 | 说明 |
|------|------|
| **无数据加密** | localStorage/IndexedDB 明文存储敏感数据 |
| **无操作审计追溯** | 只记"做了什么"，不记"改前/改后" |
| **无权限数据隔离** | 部门A能看到部门B的数据（仅UI隐藏） |
| **文件无病毒扫描** | 上传文件无安全校验 |

### 9.3 功能完整度

| 缺失功能 | 优先级 | 说明 |
|---------|:------:|------|
| 供应商真API对接 | P1 | 对接信用中国/海关企业信息公示 |
| 日历/Gantt视图完善 | P1 | 当前仅文本时间线 |
| 消息推送 | P2 | 仅页面内Toast，不在线收不到 |
| 评分权重可配置 | P2 | 40/35/25硬编码 |
| 标准与任务的关联查询 | P1 | 选了标准不能直接看相关任务 |
| 版本管理 | P2 | 标准条目更新后旧版本无法追溯 |
| 枚举约束 | P1 | 部门/状态为字符串，易写错 |

### 9.4 可维护性

| 问题 | 影响 |
|------|------|
| **1818行单文件** | 任何修改都要动整个文件 |
| **无类型检查** | 裸JS，重构时函数名改错不报错，运行时才炸 |
| **无单元测试** | 评分算法、状态机无自动化测试 |
| **无 CI/CD** | 每次修改手动部署 |
| **无代码规范** | 变量命名、文件组织靠自觉 |

### 9.5 推荐改进优先级

```
本周 (P0):  加后端 (Node.js + SQLite, 10个REST API)
本月 (P1):  真实认证对接 + 权限数据隔离
下月 (P2):  单元测试 + CI/CD + 代码拆分
持续:       安全加固 + 用户体验打磨
```
