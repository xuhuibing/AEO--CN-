## 1. 系统概述

AEO 海关认证管理系统是一个面向 **南京海关 AEO（Authorized Economic Operator）高级认证** 的企业合规管理平台。核心功能包括：

- 25项 AEO 认证标准的逐项自评与跟踪
- 任务分发、执行、审核全流程管理
- 整改问题创建→执行→验收闭环
- 内部审计计划与执行管理
- 制度文件集中管理与在线预览
- 供应商安全资质评估
- 培训计划与记录管理
- 财务报表与指标监控
- 数据版本追溯与审计日志

## 2. 架构说明

```
┌─────────────────────────────────────────────────────┐
│                    用户浏览器                          │
│  (index.html + lib/app.js + Chart.js + Tailwind)    │
└──────────────┬──────────────────────────┬────────────┘
               │                          │
               │ HTTPS (443)              │ HTTP (3080,内网)
               ▼                          ▼
┌─────────────────────────┐    ┌─────────────────────┐
│   Nginx 反向代理          │    │   Cloudflare Tunnel  │
│   (SSL + 速率限制 + 日志)  │    │   (外网访问, 可选)    │
└──────────┬──────────────┘    └──────────┬──────────┘
           │                               │
           └──────────┬────────────────────┘
                      │ HTTP (127.0.0.1:3080)
                      ▼
         ┌──────────────────────┐
         │   Node.js HTTP Server │  ← server.js (~1160行)
         │   - REST API (40+端点)│
         │   - Session 认证      │
         │   - RBAC 权限控制      │
         │   - 文件上传/下载      │
         └────┬─────────┬───────┘
              │         │
              ▼         ▼
   ┌──────────────┐  ┌──────────┐
   │   SQLite      │  │  uploads/ │
   │   (aeo.db)   │  │  文件存储  │
   │   - WAL模式   │  └──────────┘
   │   - 数据版本  │
   │   - 审计日志  │
   └──────────────┘
```

### 技术栈

| 组件 | 技术 |
|------|------|
| 运行环境 | Node.js 20 (Alpine) |
| 数据库 | SQLite (better-sqlite3) + WAL 模式 |
| 前端 | 原生 HTML + Tailwind CSS + Chart.js |
| 图标 | Font Awesome 6（自托管） |
| 认证 | Session Token (bcrypt) + Basic Auth + API Key |
| 权限 | RBAC（5种预置角色） |
| 飞书 | 开放平台 API + Webhook + 智能体 |
| 部署 | Docker / Docker Compose / Systemd |

### 数据流说明

```
用户操作 → localStorage（即时写入） → 写入队列 → 服务器 PUT /api/data/:key
                                                         ↓
                                                   SQLite data_versions 表
                                                         ↓
                                                   每6小时自动备份
                                                   每key保留最近100版本
```

**关键设计决策**：
- localStorage 作为主数据存储，服务器异步同步（保证 UI 即时响应）
- 写入队列带指数退避重试（最多3次），数据不会因网络波动丢失
- 页面加载时从服务器拉取最新数据覆盖本地缓存
- 服务器不可用时使用本地缓存数据，不影响浏览

## 4. 部署方式一：Docker（推荐）

### 4.1 获取代码

```bash
git clone https://github.com/xuhuibing/AEO--CN-.git /opt/aeo-system
cd /opt/aeo-system
```

### 4.2 配置环境变量

```bash
cp .env.example .env
# 编辑 .env 文件，修改以下配置：
#   - ADMIN_PASSWORD: 修改默认密码
#   - API_KEY: 如需API集成，设置密钥
#   - CORS_ORIGINS: 生产环境设为前端域名
vi .env
```

### 4.3 启动服务

```bash
# 前台启动（测试用）
docker compose up

# 后台启动（生产用）
docker compose up -d

# 查看日志
docker compose logs -f
```

### 4.4 验证部署

```bash
# 健康检查
curl http://localhost:3080/api/health

# 正常响应示例：
# {"status":"ok","version":"2.0.0","uptime":123,...}
```

### 4.5 常用 Docker 操作

```bash
# 停止服务
docker compose down

# 重启服务
docker compose restart

# 重新构建（代码变更后）
docker compose build --no-cache
docker compose up -d

# 查看资源占用
docker stats aeo-system

# 进入容器调试
docker exec -it aeo-system sh
```

### 4.6 Docker 数据持久化

```yaml
# docker-compose.yml 中已配置以下命名卷：
volumes:
  aeo-data:       # → /app/data (SQLite 数据库 + 备份)
  aeo-uploads:    # → /app/uploads (上传文件)
```

备份整个数据目录：
```bash
docker run --rm -v aeo-system-data:/data -v $(pwd):/backup alpine \
  tar czf /backup/aeo-data-$(date +%Y%m%d).tar.gz -C /data .
```

## 6. 部署方式三：Systemd 生产部署

### 6.1 初始化安装

```bash
# 使用 init.sh 一键安装
sudo ./init.sh

# 手动步骤分解：
# 1. 在 /opt/aeo-system 部署代码
# 2. npm install --production
# 3. 创建 data/ uploads/ 目录
# 4. 配置 .env 文件
```

### 6.2 注册 Systemd 服务

```bash
sudo cp deploy/aeo-system.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable aeo-system
sudo systemctl start aeo-system

# 查看状态
sudo systemctl status aeo-system

# 查看日志
sudo journalctl -u aeo-system -f
```

### 6.3 Systemd 服务单元说明

服务文件位于 `deploy/aeo-system.service`，包含：
- 用户降权：以 `aeo` 用户运行（非 root）
- 安全加固：`NoNewPrivileges=true`, `PrivateTmp=true`, `ProtectSystem=full`
- 自动重启：`Restart=always`，间隔 10 秒
- 资源限制：最大文件数 65536，最大进程数 4096
- 环境配置：从 `/opt/aeo-system/.env` 加载

## 7. Nginx 反向代理与 HTTPS

### 7.1 生成 SSL 证书

**方式一：Let's Encrypt（推荐）**

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d aeo.yourcompany.com
```

**方式二：自签名证书（内网使用）**

```bash
sudo mkdir -p /etc/nginx/ssl
sudo openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/aeo.key \
  -out /etc/nginx/ssl/aeo.crt \
  -subj "/C=CN/ST=Shanghai/O=Company/CN=aeo.yourcompany.com"
```

### 7.2 部署 Nginx 配置

```bash
# 复制配置
sudo cp /opt/aeo-system/deploy/nginx-aeo.conf /etc/nginx/conf.d/aeo.conf

# 编辑配置，修改 server_name 和 SSL 证书路径
sudo vi /etc/nginx/conf.d/aeo.conf

# 测试配置
sudo nginx -t

# 重载 Nginx
sudo systemctl reload nginx
```

### 7.3 配置说明

Nginx 配置已包含以下功能（`deploy/nginx-aeo.conf`）：

| 功能 | 说明 |
|------|------|
| HTTPS 终结 | TLSv1.2/TLSv1.3，强加密套件 |
| HTTP→HTTPS 跳转 | 80 端口自动 301 到 443 |
| 速率限制 | 登录 10次/分钟，API 30次/秒 |
| 连接数限制 | 单 IP 最大连接数限制 |
| 安全头 | 7 项安全响应头叠加 |
| 结构化日志 | JSON 格式 access log |
| 敏感路径防护 | 拦截 .git, .env, data/ 等路径 |
| 大文件上传 | 100MB 上限，禁用代理缓冲 |

### 7.4 验证 HTTPS 和安全头

```bash
curl -I https://aeo.yourcompany.com
# 应包含以下响应头：
#   Strict-Transport-Security
#   X-Content-Type-Options: nosniff
#   X-Frame-Options: DENY
#   Content-Security-Policy
#   Referrer-Policy
```

## 8. 环境变量配置说明

### 完整环境变量表

| 变量 | 默认值 | 必需 | 说明 |
|------|--------|------|------|
| `PORT` | 3080 | 否 | HTTP 监听端口 |
| `ADMIN_USERNAME` | aeo | 否 | Basic Auth 用户名 |
| `ADMIN_PASSWORD` | aeo2026 | **是** | **生产环境必须修改！** |
| `API_KEY` | (空) | 否 | API 集成密钥 |
| `CORS_ORIGINS` | http://localhost:3080 | 否 | 允许跨域来源（逗号分隔） |
| `FEISHU_APP_ID` | (空) | 否 | 飞书开放平台 App ID |
| `FEISHU_APP_SECRET` | (空) | 否 | 飞书开放平台 App Secret |
| `NODE_ENV` | production | 否 | 运行环境 |

### 生产环境推荐配置 (.env)

```ini
PORT=3080
ADMIN_USERNAME=aeo
ADMIN_PASSWORD=<生成随机强密码, 建议 16 位以上>
API_KEY=<生成随机密钥, 如需集成>
CORS_ORIGINS=https://aeo.yourcompany.com
NODE_ENV=production
```

### 配置优先级

CLI 参数 > 环境变量 > 默认值

```bash
# 最高优先级：命令行参数
node server.js 3080 admin mypass

# 中优先级：环境变量
export PORT=3080
node server.js

# 低优先级：代码中的硬编码默认值
```

```sql
-- 查看指定 key 的版本历史
SELECT id, username, created_at, description 
FROM data_versions 
WHERE data_key = 'tasks' 
ORDER BY id DESC LIMIT 20;
```

## 13. 常见问题排查

### 13.1 服务无法启动

**现象**：`Error: listen EADDRINUSE :::3080`
**原因**：端口被占用
**解决**：
```bash
# 查找占用进程
lsof -i :3080
# 终止旧进程
kill <PID>
# 或使用不同端口
PORT=3081 node server.js
```

### 13.2 SQLite 数据库锁定

**现象**：`SQLITE_BUSY` 错误
**原因**：并发写入过多
**解决**：系统已启用 WAL 模式，正常情况下不应出现。如出现：
```bash
# 重启服务即可
systemctl restart aeo-system
```

### 13.3 文件上传失败

- 检查 `uploads/` 目录权限
- 检查文件类型是否在允许列表中（PDF, JPG, PNG, GIF, XLSX, DOCX, ZIP, TXT, CSV）
- 检查文件大小是否超过 50MB 限制
- 检查磁盘空间

### 13.4 登录提示"服务器连接失败"

原因之一：
1. 服务器未启动 → 检查服务状态
2. 防火墙拦截 → 检查 3080 端口可达性
3. Nginx 代理配置错误 → 检查 Nginx 日志
4. Session token 过期 → 重新登录

### 13.5 数据不同步

如果前端显示"同步失败"：
1. 检查网络连接
2. 刷新页面触发 `initFromServer()` 拉取服务器数据
3. 检查服务器端 `data_versions` 表是否有对应记录
